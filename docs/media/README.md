## 拍之前

- **用演示项目。** 用一个公开的开源仓库或专门建的演示项目，不要用公司项目和私人代码。
- **不能有个人信息。** 用户名、公司名、内网路径都不能出现；路径最好像 `D:\demo\todo-app`。有些企业安全软件会在整个屏幕上叠加带姓名的水印，在这样的电脑上截的图不能公开，要换一台干净的机器或虚拟机。
- **窗口和字号。** 窗口客户区 1600×1000，缩放 100%，深色主题，中文界面；终端字号 15、界面 14 左右，缩到 README 的宽度（约 900px）还能看清。
- **等新样式上线。** 状态颜色和标签样式改成了红绿灯（路线图 G16），`status.png`、`workspaces.png` 和视频要用带新样式的版本拍。

## 演示视频（约 60 秒）

1. **0–8 秒**：打开演示项目，终端占满窗口；标题栏有几个工作区标签。
2. **8–18 秒**：在终端里运行 `claude`，提一个小需求；标签开始显示工作中。切到另一个工作区标签，那里的 agent 在等你回复，回它一句。
3. **18–30 秒**：回到第一个标签，点 agent 输出里的一个文件路径，编辑器从右边打开；再点一段 mermaid，看到图。
4. **30–45 秒**：这一轮做完，点"N 个文件已修改"，打开审阅，撤回其中一块，写一条意见发回给 agent。
5. **45–60 秒**：关掉 Solo 再打开，agent 终端还在，接着工作。

逐镜头的分镜、要截的 12 张图和合成脚本在 [`script/demo-video/`](../../script/demo-video/README.md)，分镜文件是 [`video/scenes.json`](video/scenes.json)，截图放 `video/shots/`。

## 视频怎么做

三种做法，用的是第一种：

1. **真截图 + 代码合成（采用）。** 在干净的环境里按分镜每一步截一张图，再用 `script/demo-video/render.py` 合成：加中文字幕、镜头推拉、高亮和鼠标点击、做转场。画面都是真实界面，又不用一次录成；截图更新后重新跑脚本就行。脚本只用 Python 和 Pillow 出逐帧 PNG 和动图预览，编成 MP4 要 ffmpeg。
2. **直接录屏。** OBS 或 ScreenToGif，宽 1280、30 帧，导出 MP4（H.264），控制在 10 MB 以内。
3. **纯代码画的示意动画。** 不用真截图，按设计稿用代码画界面再做成动画。只能当"示意"用，容易和真实界面对不上，不建议放在 README 最上面。

放进 README：在 GitHub 的 issue 或 PR 编辑框里拖入 MP4，会得到一个 `https://github.com/user-attachments/…` 链接，把它单独放一行，GitHub 会显示成播放器（这是 GitHub 当前的做法，以实际效果为准）。GIF 可以直接放在本目录。
