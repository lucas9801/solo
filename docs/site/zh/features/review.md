# 按轮审阅：agent 每一轮改了什么

[← 首页](../index.md)

agent 一口气改十几个文件很常见。等它全部做完再看 `git diff`，你分不清哪些改动是为了哪一步，也很难只撤回其中一部分。Solo 按 agent 的"轮"来记录：你发一次提示、它干完一段活，就是一轮。

## 怎么用

1. 在 Solo 的终端里正常运行 agent，比如 `claude`。
2. 它每结束一轮，终端标签上会出现 **"N 个文件已修改"**。
3. 点开就是审阅界面，按文件列出这一轮的改动：
   - 每个改动块可以**保留**或**拒绝**，也可以全部保留、全部拒绝；
   - 在代码行上写意见，最后**一次发回给 agent**，它会照着改；
   - 需要的话**回滚到这一轮之前**，回滚也能撤销。

## 诊断增量：这一轮有没有改坏东西

一轮结束后，Solo 会打开改过的文件，等语言服务器（rust-analyzer、clangd、TypeScript 等）检查完，再和这一轮开始时的结果比较，在审阅界面顶部写出：

> 这一轮新增 2 个错误、1 个警告，修掉了 3 个错误

下面列出每个新问题的位置和信息，点一下就跳过去。只统计这一轮改过的文件，原本就有的问题不算在里面。

没有对应语言服务器、或者检查超过一分钟没完成时，会写明"未检查"，不会假装没问题。

## 审阅界面就是编辑器

审阅时可以像平时一样读代码：跳到定义、查引用、在文件里搜索，看完再回来。每个改动块上方写着它所在的函数或类型，不用往上翻找上下文。

## 你的仓库不会被动到

- 快照存在 Solo 自己的数据目录里，不改你的分支、HEAD、暂存区和 stash，也不往 git 对象库里写东西。
- 拒绝一个改动块时，只恢复那一块，同一个文件里的其他改动保留。
- 被 `.gitignore` 忽略的文件不在快照里。

## 支持哪些 agent

| agent | 怎么知道一轮的开始和结束 |
| --- | --- |
| Claude Code、Codex、Copilot CLI | Solo 为这次会话加上 hooks，由 agent 自己上报，最准确。不改你的配置 |
| Gemini CLI、Cursor CLI、OpenCode、Qwen Code、Amp 等二十多种 | 按每种 agent 的屏幕规则判断（规则来自开源项目 Herdr），可能慢一点 |
| 其他程序 | 可以按 [状态协议](../../../agent-status-protocol.md) 自己上报 |

Claude Code 还多一样东西：**会话时间线**，按轮列出提示词、读过和改过的文件、跑过的命令和最后的回答。
