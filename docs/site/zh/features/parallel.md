# 让几个 agent 同时干活

[← 首页](../index.md)

## agent 任务：每个任务一个 worktree

几个 agent 在同一个目录里同时改代码，会互相踩脚。Solo 的做法是给每个任务一个独立的 git worktree 和分支：

1. 在标题栏的项目标签菜单里选 **新建 agent 任务**（或者命令面板里的 New Agent Task），写个任务名。
2. Solo 从当前分支建一个新分支和对应的 worktree，在里面开一个终端，启动你设定的 agent（默认 `claude`）。
3. 做完后在 **管理 agent 任务** 里：查看 diff、**合并回原分支**、**推送并开 PR**，或者删除。

- 任务记在仓库自己的 git 配置里，重启后还在。
- 合并前会列出要合并的提交和没提交的改动；有冲突时自动放弃这次合并，不会把你的主工作区弄成一半。
- 任务还有没提交的改动时，可以点 **让 agent 提交**：Solo 把请求粘贴给这个任务的 agent，让它根据 diff 写提交信息再提交。Solo 自己不调用任何模型。
- 开了 PR 以后，**把 PR 反馈发给 agent** 会把失败的 CI 检查和 review 评论整理好交给它。（需要 `gh` 命令行工具）

### 横跨几个仓库

前端、后端、共享库分在几个仓库里，一个需求要一起改？把这几个仓库加到同一个工作区，新建任务时勾选 **同时在工作区的其他仓库里建**。每个仓库都在同名的新分支上建一个 worktree，并排放在一个以任务命名的文件夹里，agent 在这个文件夹里启动，能同时看到所有仓库。每个仓库的部分分别合并、开 PR 或删除。

### 仓库自己的任务配置

在仓库里放一个 `.solo/tasks.json`，可以决定 worktree 放在哪、每个任务复制哪些被忽略的文件（比如 `.env`）、启动 agent 前跑什么命令、删除前跑什么命令，以及给每个任务分一个独立端口。

## 看清谁在干什么

- **终端标签** 显示 agent 的状态：工作中、等你输入、空闲、完成、失败。Solo 在后台时，有 agent 等你或者干完一段较长的活，会发桌面通知。
- **标题栏的工作区标签：** 一个项目一个标签，切换时终端、编辑器、文件树一起换。每个标签上统计这个项目里正在工作、等你回复、失败的 agent 数量，后台项目里有 agent 在等你也看得到。标签菜单里列出这个项目的终端和任务，点一下就跳过去。
- **agent 看板：** 左侧栏里列出所有 agent 和任务，等你输入的排最前面。

## 让 agent 指挥 agent

Solo 终端里的 agent 可以用 `solo-cli agent` 查看和驱动其他终端：

```
solo-cli agent ls                     # 所有终端和它们的状态
solo-cli agent new-task --prompt "…"  # 新开一个任务，交给另一个 agent
solo-cli agent wait <id>              # 等它做完
solo-cli agent output <id>            # 读它最后的回答
solo-cli agent send <id> "…"          # 给它发消息
```

比如让主 agent 把一个子任务交出去，自己接着干，回头再收结果；或者请另一个 agent 给出第二意见。把 [这份说明](../../../agent-cli.md) 给 agent 看，它就会用。能做到什么程度由设置 `agent_control` 控制（完全、只读或关闭），每次调用都有记录。
