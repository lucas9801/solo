Solo 2.5.5: rejecting an agent's change restores the file byte for byte, pending turns and unsent rejections and comments survive a restart, plus fixes to pending changes and the update menu.

## 修复

- **拒绝改动后文件没有原样还原：** 拒绝时整个文件会被统一成一种换行，CRLF 和 LF 混用的文件拒绝后 git 仍显示有改动。现在只替换拒绝的那几行，其他行的换行和 BOM 保持磁盘上的原样，还原的行和你认可时一模一样。
- **重启后待审改动丢了一部分：** 更新重启或重新加载后，审阅页的"轮次"变成 (0)，还没发给 agent 的拒绝和批注也不见了。现在它们都保留下来，可以照常查看、回滚和发送；发出去之后不会再出现。只能复制、没能直接发给 agent 时，这些内容也会留着，之后可以再发。
- **同一文件连着拒绝几处：** 很快连点几次拒绝时，后一次可能盖掉前一次，或把 agent 删掉的行插回两次。现在同一文件的拒绝按顺序进行，只处理你点的那几处；文件在拒绝期间被改动了，就不拒绝并说明原因，不会悄悄什么都不做，也不会写出编辑器里看不到的内容。
- **更新菜单：** 英文界面里新版本的简介首字母现在是大写。

## Fixes

- **Rejected changes didn't restore the file exactly:** rejecting rewrote the whole file with one kind of line break, so a file mixing CRLF and LF still showed as modified in git. Now only the rejected lines are replaced; the other lines keep their line breaks and BOM as they are on disk, and the restored lines are exactly as you accepted them.
- **Part of the pending changes was lost on a restart:** after an update restart or a reload, the review page showed "Turns (0)", and rejections and comments not yet sent to the agent were gone. They're kept now: you can look, roll back and send as usual, and once sent they don't come back. When they could only be copied instead of sent to the agent, they're kept too, to send later.
- **Several rejections in one file:** rejecting several hunks quickly could undo an earlier rejection or insert lines the agent deleted twice. Rejections in one file now run in order and touch only the hunks you chose; when the file changes meanwhile, Solo doesn't reject and says why, instead of doing nothing silently or writing something the editor doesn't show.
- **Update menu:** in the English interface, a new version's summary now starts with a capital letter.
