Solo 2.4.2：终端里点击目录不再加成项目根目录，切换工作区后光标落在终端里；并修复商店版没通过认证的问题。
Solo 2.4.2: clicking a directory in a terminal no longer adds it as a project root, switching workspaces puts the cursor in the terminal, and the Microsoft Store package now passes certification.

[用户指南](https://github.com/lucas9801/solo/blob/main/docs/guide/zh-CN.md) · [User guide](https://github.com/lucas9801/solo/blob/main/docs/guide/en.md)

## 修复

- **点击目录不再加成根目录：** 在终端或 Markdown 预览里 Ctrl+点击一个目录，以前会把它加成工作区的根目录（点到 `G:\` 会扫描整个盘，Solo 明显变卡），重启后还在。现在目录在项目里时，文件树展开并选中它；不在项目里时，用资源管理器打开。已经加进去的根目录不会自动删除，可以在文件树里右键移除。
- **切换后光标在终端里：** 切换工作区（点标签、`Ctrl+Alt+数字`、`Ctrl+Alt+PageUp/PageDown`、标签菜单）后，终端面板开着时光标落在终端里，"完成待查看"随之清除，不用再点一下。从标签菜单、agent 看板或通知跳到某个终端时，会先切到它的工作区、打开终端面板再聚焦。从别的程序切回 Solo 时，焦点所在终端的"待查看"也会清除。
- **商店版没通过认证：** 商店没有批准安装包申请的受限权限 unvirtualizedResources。现在包里不再申请它：商店版 Solo 终端里运行的程序在包外启动，写入的仍是真实的 AppData；Solo 交给终端的脚本和程序放在包自己的数据目录里。

## Fixes

- **Clicking a directory no longer adds a root:** Ctrl+clicking a directory in a terminal or a Markdown preview used to add it as a root of the workspace (clicking `G:\` scanned the whole drive and slowed Solo down), and it stayed after a restart. Now a directory in the project is expanded and selected in the project panel, and one outside it opens in File Explorer. Roots added before aren't removed; remove them from the project panel's context menu.
- **The cursor stays in the terminal after switching:** after switching workspaces (clicking a tab, `Ctrl+Alt+number`, `Ctrl+Alt+PageUp/PageDown`, the tab menu) with the terminal panel open, the cursor is in the terminal and "finished, not yet seen" clears without another click. Jumping to a terminal from the tab menu, the agent board or a notification switches to its workspace and opens the terminal panel first. Coming back to Solo from another program also clears it for the focused terminal.
- **The Store package failed certification:** the Store didn't grant the restricted capability unvirtualizedResources. The package no longer asks for it: in the Store edition, what runs in Solo's terminals starts outside the package and still writes to the real AppData, and the scripts and programs Solo hands its terminals go to the package's own data folder.
