Solo 2.5.3：终端大量输出时 CPU 大幅下降，项目搜索和新窗口的终端更快，agent 的钩子文件不再被清理软件删掉，没有状态报告的 agent 会在悬停卡片上标出来。
Solo 2.5.3: much less CPU while terminals print a lot, faster project search and terminal startup, agents' hook files no longer lost to temp cleaners, and the hover card marks agents that run without status reports.

## 新功能

- **悬停卡片标出没有状态报告的 agent：** agent 启动时没带上 Solo 的钩子，或者启动后 15 秒还没报告过状态，终端标签的悬停卡片会在状态上加一个警告图标，并写明"状态是从屏幕上读的，开一个新终端就好"。点这行字能看到和"为什么是这个状态？"一样的说明；钩子文件缺失时还会说明这次会话不会列出改过的文件。
- **"为什么是这个状态？"也说明钩子的问题：** 上面两种情况都会写出来；`solo-cli agent why --json` 多了 `hooks_missing` 字段。
- **发布页多了固定名字的安装程序：** 每个版本都附带 `Solo-Setup.exe`，用 `releases/latest/download/Solo-Setup.exe` 这个链接总能下到最新版。

## 修复

- **钩子文件被清理：** 清理软件清空 %TEMP% 后，agent 会悄悄地不带钩子启动，没有状态报告，每轮也不列改过的文件。现在 GitHub 安装版把这些文件放在 Solo 的数据目录（%LOCALAPPDATA%\Solo\solo-shell-integration），缺了会自动补写；实在补不回来时，终端里会打一行提示。

## 性能

- **终端大量输出：** 10 个终端同时持续打印时，Solo 的 CPU 从约 3 个核降到约 0.2 个核。以前每批输出都要重新读一次进程信息来更新标题，现在最多每 0.5 秒读一次（程序自己打印、你没输入时每 5 秒），后台标签里的终端也不再反复重绘。
- **项目搜索：** 在大仓库里搜索快了约三分之一到一半。默认开着的行内 blame 以前会对每个结果文件跑 `git blame`，结果每多一批就全部重跑一遍；现在只 blame 真正要显示的那个文件。
- **新窗口的终端：** 本地 PowerShell 终端能输入的时间提前约 0.3 秒，不再先多起一个 PowerShell 读环境变量。
- **语言服务器内存显示：** 只在进程可能有变化时才扫描全部进程，空闲时的 CPU 也低了一些。

## New

- **The hover card marks agents without status reports:** when an agent started without Solo's hooks, or hasn't reported in its first 15 seconds, the card on its terminal tab shows a warning icon on the status and says the status is read from the screen and a new terminal fixes it. Clicking the note shows the same explanation as "Why This Agent Status?"; when the hook files were missing, the card also says changed files won't be listed for this session.
- **"Why This Agent Status?" explains missing hooks:** both cases are described there, and `solo-cli agent why --json` has a `hooks_missing` field.
- **An installer with a fixed name:** every release also has `Solo-Setup.exe`, so `releases/latest/download/Solo-Setup.exe` always gets the newest version.

## Fixes

- **Hook files lost to cleaners:** after a temp cleaner emptied %TEMP%, agents started without their hooks without saying so: no status reports and no changed files listed per turn. The GitHub installer edition now keeps these files in Solo's data folder (%LOCALAPPDATA%\Solo\solo-shell-integration) and writes missing ones again; if they can't be restored, the terminal prints one line saying so.

## Performance

- **Terminals printing a lot:** with 10 terminals printing continuously, Solo uses about 0.2 of a core instead of about 3. Every batch of output used to read the terminal's process again for its title; now that happens at most every 0.5 s (every 5 s while a program prints on its own), and terminals in background tabs no longer redraw the window over and over.
- **Project search:** a third to a half faster in large repositories. Inline blame, on by default, ran `git blame` for every result file and again each time more results came in; now it blames only the file it shows.
- **Terminals in a new window:** a local PowerShell terminal is ready about 0.3 s sooner, without first starting another PowerShell to read the environment.
- **Language server memory:** all processes are scanned only when the servers' processes may have changed, which lowers idle CPU a little.
